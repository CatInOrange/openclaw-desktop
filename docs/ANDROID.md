# OpenClaw Android 0.1.4 — 连接版

这是独立 Android 原生壳，使用系统 WebView 加载现有 Gateway Control UI。它不是 Electron APK，也不包含 Windows 的 Node 运行时、视频壁纸或桌宠大素材。

## 安装与连接

- Android 9（API28）及以上，设备需要可用且较新的系统 WebView。
- 安装 `OpenClaw-Android-0.1.4.apk`，按系统要求允许此来源安装。
- 输入手机能访问的 Gateway 地址。手机的 `127.0.0.1` 是手机本身，不是电脑；请使用手机可达的 LAN/VPN/HTTPS 地址。
- 优先使用有效证书的 HTTPS。HTTP 可以由用户明确配置，但 WebCrypto/设备身份等能力受安全上下文限制，不能保证在明文地址下完成认证。
- 登录、设备配对和模型/会话功能仍由原版 Control UI 提供，不修改 Gateway，不把 Token 放入入口地址。

## 首版范围

原生地址设置、入口校验、独立浏览器登录空间、站内浏览与返回、加载错误/重试、系统文档选择及安全外链处理。Gecko Cookie/本地存储保留在应用私有数据目录；升级沿用同一 applicationId 和发布签名，不要求每次重新登录。清除应用数据或卸载会清除本机登录。

不同 Gateway origin（协议、主机、有效端口）使用不同 Gecko profile 目录，避免跨服务器混用会话。首连可以直接创建对应空间；切换到不同 origin 需要受控退出并重新打开，旧空间仍保留。相同 origin 的路径变化不要求新建登录空间。

首版不支持音乐、锁屏播放、语音录制、摄像头授权、桌宠或后台常驻/消息推送。网页语音按钮不表示应用已授予麦克风权限。附件选择接入系统文档界面，不申请全部存储权限；实际附件上传、键盘和配对体验需真机验收。

## 共用与独立部分

- 服务器 Control UI 由两端共用，不复制前端。
- `shared/core/music-controller.cjs` 是唯一纯业务实现，桌面端通过兼容入口使用；Android 音乐运行时和 Media3 后台服务尚未集成，不声称当前 APK 已执行它。
- `shared/contracts/gateway-cases.json` 同时约束桌面 JS 与 Android Kotlin 地址/origin 策略。
- `assets/icon.png` 是两端图标的唯一源素材，CI 调用 `scripts/sync-android-assets.py` 生成 Android 密度资源，不手工维护两份图标。
- GeckoView、文件选择、系统返回、生命周期、签名安装属于 Android 适配层。

## 构建与签名

所有编译、打包和交付检查均在 GitHub Actions 执行，不在用户 Linux 主机运行 Gradle/Android 构建，也不运行模拟器或虚拟显示。流程位于 `.github/workflows/android.yml`。

工具链固定 JDK17、Gradle9.3.1（wrapper SHA256固定）、AGP9.1.1（内置 Kotlin，KGP 固定2.4.21）、compile SDK37 / target SDK35。该 APK 用于个人侧载验证，不代表已符合应用商店上架要求。

正式发布使用持久私有签名，私钥及密码不在代码、APK、构建产物或聊天里。公开证书指纹在 `shared/android-signing-certificate.sha256`，CI 检查 APK 签名、包名、版本、最低 API、非调试标记、权限与备份限制。后续更新必须延续相同包名/签名并增加 versionCode。

## 真机验收

1. 手机安装、打开、输入可达的 HTTPS Gateway，完成设备配对和登录。
2. 彻底退出再打开，确认保留 Gateway 地址及登录空间。
3. 输入中文、打开/关闭键盘，确认输入框不被挡；切换会话、返回键导航正常。
4. 选择本地图片/文件并发送；取消选择不应卡住网页；外链在浏览器打开。
5. 暂时断网后重试，切后台/旋转后恢复不应反复重建页面或清空登录。
6. 切换不同 origin 时遵循提示重新打开，不应串用登录；切回原 origin 应恢复其私有空间。

非 GUI 编译、JVM测试、lint和APK检查不等同于上述真机验收。首次 APK 重点证明聊天连接闭环，再逐步接入经过独立验证的共享音乐业务。

## 0.1.2 启动修复

根据 HUAWEI PLA-AL10 / Android 12 的异常堆栈，将系统栏外观设置延迟至根视图挂载后，避免提前调用 PhoneWindow.getInsetsController。覆盖安装后若仍进入旧诊断页，点击「清除记录并重试」。真机启动和界面仍需用户验收。

### 应用内更新

在「设置 → 检查应用更新」检查稳定 Android Release（与桌面版分流），下载后检查 SHA-256、包名、递增版本及固定发布签名，再交给系统安装。诊断页也提供更新入口。首次按系统要求允许本应用安装更新，返回再点安装；无需卸载，登录保留。下载时留在更新页，网络失败可重试；不做静默安装、后台保活或断点续传。

## 0.1.3 内嵌 Gecko 验证版

- 固定 Mozilla 官方 `org.mozilla.geckoview:geckoview:160.0.20261116130455`，不修改或本地编译内核。不依赖系统 WebView。当前验证包仅 ARM64，Android 9+。
- GeckoRuntime 每进程单例，按 Gateway origin 使用持久私有 profile；切换 origin 需退出重开。原 WebView 数据不删除但不迁移，首次需重新登录/配对；后续 Gecko 登录保持待真机验证。
- 无远程原生 JS bridge，限制顶层导航至已选 Gateway，不忽略 TLS 证书错误；拒绝额外网页权限，文件仅由用户通过系统选择器授权。Gecko 负责标准网络与混合内容策略；旧 WebView 的自定义逐子资源拦截不是 Gecko API 的等价功能，不宣称已经复用。
- 单文件选择上限 25 MB，最多 10 个文件；私有临时副本启动时清理超过24小时的文件。文件夹上传不支持。
- 更新入口继续使用原生下载/签名校验/系统安装链路，CI 限制 APK 不超过已安装0.1.2更新器的100MB上限。
- 动态背景、桌宠、音乐不在本次验证范围；容器继续保留独立 FrameLayout，后续扩展需验证透明绘制与触摸层级。

### 第三方内核与维护

GeckoView 是未修改的 Mozilla 官方预编译组件，按 MPL-2.0 等上游许可证分发，内含第三方许可证见 Gecko 的 `about:license`。官方源码与构建信息： https://firefox-source-docs.mozilla.org/mobile/android/geckoview/ 、 https://hg.mozilla.org/releases/mozilla-release/ 。后续跟进官方稳定/安全版本，依赖固定版本并由 GitHub 构建，升级后真机回归，不长期冻结内核。

## 0.1.4 COS 更新线路

更新页读取构建时注入的固定 HTTPS 清单地址，从同源 COS 下载公开可读 APK ZIP，自动解压并校验内层 APK。校验 SHA-256、包名、递增版本和固定签名后由系统确认安装；不携带 COS 上传密钥。

真实更新地址和 COS 配置仅放 GitHub Secrets，不提交源码、Release 说明或日志。客户端下载时仍可观察地址。COS 默认域名不直接分发 APK，因此使用与 AliceChat 一致的 ZIP 封装；首次从旧版迁移需下载 ZIP、解压并手动覆盖安装一次，之后在应用内检查更新。

发布：在分支通过检查后，手动运行 Android workflow（publish=true）。CI 上传版本目录后最后替换 latest.json；普通 push/PR 不发布。清单禁用缓存，历史安装包使用版本路径；COS 对象独立于 AliceChat。所需 Secrets：ANDROID_UPDATE_MANIFEST_URL、COS_BUCKET、COS_REGION、COS_SECRET_ID、COS_SECRET_KEY，以及既有 Android 签名配置。

## 0.1.5 视频与外观

复用桌面版同源、同许可的视频：约8秒有声开机动画、静音循环动态背景。
设置 → 视频与外观：动画、声音、背景独立开关，背景强度和毛玻璃透明度即时保存。
开机动画每次进程启动仅播一次，不因刷新、重连、切后台重播；无跳过按钮，失败自动回退。
后台暂停媒体；Control UI 与动画并行加载。背景只在当前 Gateway 顶层页面启用。
使用 Gecko 内置隔离扩展，仅向原生读取白名单外观配置，不向网页开放原生操作桥，不修改服务端 CSP。

真机验收：从0.1.4检查更新并覆盖安装；确认开屏声画、竖/横屏背景、浅深色可读性、设置持久化、后台静音和恢复、刷新不重播、登录/附件不受影响。GUI及实际解码需用户手机验证。

## 0.1.6 静音背景播放修复

0.1.5 的网页权限回调统一拒绝所有权限，也拒绝了 GeckoView 的静音自动播放请求。
仅对已配置 Gateway 同源页面放行 `PERMISSION_AUTOPLAY_INAUDIBLE`；有声自动播放、其他来源和其他权限继续拒绝。开屏原生视频不受此回调影响。
真机需验收冷启动后背景播放及后台暂停/恢复。
升级时还会修正该 Gateway 已存储的静音自动播放拒绝记录，不清除登录状态或其他权限。

## 0.1.7 背景资源与诊断

Android 扩展将本地视频读为 data: 媒体，避免扩展 Blob 来源与页面来源之间的加载边界；不修改 Gateway CSP。原生消息/读取失败采用退避重试，不再一次失败永久关闭。视频与外观页提供扩展状态、媒体错误码、readyState 与播放秒数。云端编译与非 GUI 检查不能替代手机验收。

## 0.1.8 扩展私有视频数据

0.1.7 真机返回 outer-catch 的 `error · Error · ready=0`，尚不能据此区分读取失败或渲染异常；不将推测当成真机根因。移除内容脚本的 fetch/FileReader 路径：CI 从同一许可 MP4 生成扩展私有脚本数据，由固定 runtime 消息在原生同源授权之后提供。无远程视频、任意文件读取或新增网页原生操作。APK 检查解码派生数据并比对原始 MP4 SHA256。错误诊断保留白名单阶段及异常类型，不包含地址、凭据或异常原文。手机实际效果仍需验收。

## 0.1.9 原生设置回传

设置响应使用 JSON 字符串跨越 Gecko EventDispatcher 边界，扩展解析后再做授权和播放；不能直接回传 JSONObject。此前仅模拟普通 JS 对象的测试未覆盖该边界。设备截图已确认 0.1.8 在 native-settings 阶段失败；本版真机播放仍需验收。

## 0.2.0 原生心动音乐与下载进度

- 顶部迷你播放条提供播放/暂停、红心和下一首，点歌名打开底部音乐面板。与 Gateway / Gecko 页面完全隔离，刷新或切换会话不影响播放。
- Kotlin 窄协议适配器基于固定版本 `@neteasecloudmusicapienhanced/api@4.41.1` 的 endpoint/payload 和 eapi/weapi 信封移植；手机直接 HTTPS 请求网易云，不依赖第三方代理服务或新增 Gateway 接口。不是官方 SDK；不解锁、换源、伪造地区。
- 登录支持二维码（可分享图片后尝试网易云扫一扫相册识别）和 +86 短信验证码。服务器风控可能拒绝短信，此时回退扫码。短信仅在用户点击发送时请求；登录后不自动发声。没有复制桌面或开发机的 Cookie。
- AndroidKeyStore AES-GCM 加密保存登录态，失败时只维持当前会话，退出登录清除本地凭据。账号会话不进入 Control UI、日志、Bundle 或备份。
- 原生前台媒体服务 + MediaSession + MediaPlayer 承载后台和锁屏播放、通知播放/暂停/下一首/停止。失去音频焦点或拔耳机暂停；不会擅自恢复播放。划掉最近任务或通知「停止」销毁服务，重开不自动播放。
- 保留红心种子心动推荐，不切换 FM/日推；去重续补，有限推荐池循环，试听/不可播跳过，失败次数有界。没有搜索、歌词或音乐下载。
- 更新页面展示下载百分比和已下载/总 MB，完成后明确显示签名校验阶段。正在运行的旧版更新器不会因下载新版而即时获得新界面，安装 0.2.0 后的下次下载可见进度。
- JVM 验证协议加密向量（对照 Node 固定依赖）、随机密钥不复用、队列多轮续播/去重/回收/退出清理。未将云端测试冒充为真机发声验收。

真机验收：短信或扫码 → 播放 → 暂停/恢复 → 下一首/红心 → 自然结束自动续播 → 锁屏/切应用/切会话/刷新不断播 → 耳机断开/其他音频打断暂停 → 通知停止/最近任务划掉停止 → 重开保留登录但不自动发声。
